2. ESTRUCTURA FINAL DEL ESQUEMA 1.1

Un unico problema.json contiene:
- schema_version = "1.1";
- metadata;
- problem.type;
- problem.variables y problem.constraints para elementos explicitos;
- problem.sets y problem.parameters;
- problem.variable_families 1D o 2D;
- problem.bio_objectives con coefficients e indexed_terms;
- problem.constraint_families 1D o 2D;
- index_ranges opcional para acotar una expansion.

El flujo observado es:
  JSON 1.0 o 1.1
  -> deserialize_model()
  -> expansion 1.1 a forma explicita canonica dispersa
  -> build_biobjective_problem_from_state()
  -> Pyomo + HiGHS
  -> epsilon-constraint o ponderaciones normalizadas

La salida 1.1 conserva:
- source_provenance para variables, restricciones y parametros;
- expansion_statistics con conteos explicitos, generados y totales;
- solo coeficientes distintos de cero.

El esquema 1.0 no se migra ni cambia de significado. El modelo
models/hidroelectrica_biobjetivo.json continuo cargando como 1.0 con 24
variables y 28 restricciones.
