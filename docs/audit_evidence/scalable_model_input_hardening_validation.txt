DEFECTOS CORREGIDOS
1. Una expresion calculada con sum([]) producia el entero Python 0. Al comparar
   ese valor con el RHS, Pyomo recibia True/False y lanzaba
   InvalidConstraintError antes de ejecutar HiGHS.
2. La salvaguarda temporal de nombres no incluia component_map ni obj, y el
   editor manual y JSON no compartian la validacion de la importacion masiva.

SOLUCION APLICADA
- pyomo_utils.build_linear_expression crea pyo.quicksum para terminos no nulos.
- Cuando no existen terminos, devuelve 0.0 multiplicado por la primera variable
  Pyomo. El cero permanece simbolico y no modifica la region factible.
- lp_solver y multiobjective reutilizan exactamente el mismo helper para las
  restricciones originales.
- validate_variable_names es la fuente unica de la salvaguarda temporal para
  bloque, formato ancho, formato disperso, controlador del editor manual y JSON.
- apply_manual_variable_rename preserva la migracion posicional existente, pero
  valida atomicamente antes de modificar session_state.
- AUD-HIGH-06 permanece ABIERTO: no se introdujeron IDs internos.

RESTRICCIONES CONSTANTES
0 <= 10 -> optimal; LHS=0; slack=10.
0 >= 10 -> infeasible.
0 = 0 -> optimal; LHS=0; slack=0; activa con la tolerancia vigente.
0 = 10 -> infeasible.

PROYECCION DE VARIABLES
Secuencia: variables x1,x2; R1: x1 <= 10; apply_variable_import([x2]).
Resultado canonico: coefficients={}; resolucion posterior: optimal, sin crash.
Variante R1: x1 >= 10 proyectada a 0 >= 10: infeasible, sin crash.
